# PWA: як це працює і як перевірити

Bookshelf встановлюється на телефон як звичайний застосунок: власне вікно, значок на головному екрані, запуск без адресного рядка.
Усе зроблено без сторонніх бібліотек (ні Workbox, ні `vite-plugin-pwa`): логіка Service Worker невелика, і її повністю покривають тести.

## Що саме є

| Що | Де | Для чого |
|---|---|---|
| Маніфест | `frontend/public/manifest.webmanifest` | назва, іконки, `standalone`, ярлики («Додати цитату», «Статистика»), приймання тексту з інших застосунків |
| Іконки | `frontend/public/icons/*`, `apple-touch-icon.png`, `favicon.svg` | малює `frontend/scripts/make-icons.py` (Pillow); `maskable` лишає поля для круглих і «білкових» масок Android |
| Service Worker | `frontend/src/sw/` | `strategy.ts` (що робити з запитом), `worker.ts` (обробники подій), `sw.ts` (точка входу) |
| Збірка воркера | `frontend/vite.sw.config.ts` | другий крок `npm run build`: рахує список файлів у `dist/` і хеш версії, пише `dist/sw.js` |
| Реєстрація й оновлення | `frontend/src/pwa/updates.ts` | реєструє воркер, помічає нову версію, перемикає на неї за згодою читача |
| Мережа | `frontend/src/pwa/online.ts`, `api/http.ts` | банер «Немає інтернету», `NetworkError`, ліміт очікування 20 с |
| Встановлення | `frontend/src/pwa/install.ts`, `InstallCard.vue` | кнопка «Встановити» (Chrome/Android) або підказка для Safari на iPhone, на екрані «Профіль» |

## Що кешується, а що ні

- **Кешується оболонка застосунку:** `index.html`, скрипти, стилі, іконки, маніфест. Вони кладуться в кеш `bookshelf-shell-<версія>` під час встановлення воркера, тому застосунок відкривається без мережі.
- **Дані читача ніколи не кешуються:** `/api/*`, `/docs`, `/up` воркер не чіпає. Книги, цитати й статистика завжди беруться з сервера, тож чужі дані не можуть лишитися на спільному пристрої, а застарілих даних не буває.
- **Наслідок:** офлайн відкриється оболонка, але без даних; замість них буде екран «Немає з’єднання» з кнопкою «Повторити». Офлайн-оновлення прогресу з подальшою синхронізацією свідомо винесено в backlog.
- Обкладинки з Open Library — чужий сайт; воркер їх не чіпає.

## Оновлення версії

1. Кожен деплой дає інший хеш файлів, отже інший `sw.js`. Браузер перевіряє `sw.js` при кожному відкритті застосунку і коли той повертається на екран.
2. Нова версія завантажується у фоні й **чекає**: сама на себе не перемикається, щоб не перезавантажити екран із недописаною цитатою.
3. Читач бачить банер «Доступна нова версія застосунку» і тисне «Оновити». Воркер перемикається, сторінка перезавантажується один раз.
4. Старий кеш видаляється при активації нової версії.

`sw.js` і `manifest.webmanifest` віддаються з `Cache-Control: no-cache` (див. `docker/web/nginx.conf`), інакше браузер сидів би на старому воркері. Файли з `/assets/` мають хеш у назві й кешуються на рік.

## Розробка

- У dev-режимі (`make up`) воркер **не реєструється**, а якщо на цій адресі колись лишився воркер від продакшн-збірки, він сам видаляється разом із кешем.
- Перевірити продакшн-збірку локально: `docker compose exec frontend npm run build`, далі віддати `frontend/dist` тим самим nginx-конфігом, що й на проді (`docker/web/nginx.conf`) і відкрити в браузері. Воркеру потрібен безпечний контекст: підійдуть `localhost`, `127.0.0.1` і HTTPS.
- Скинути все в браузері: DevTools → Application → Service Workers → Unregister, і Storage → Clear site data.
- Перемалювати іконки: `python3 frontend/scripts/make-icons.py`.

## Автоматичні перевірки

- `strategy.spec.ts`: які запити воркер бере на себе (навігація → оболонка, `/assets` → кеш, `/api` → нічого, не-GET і чужі сайти → нічого).
- `worker.spec.ts`: встановлення, активація, перемикання за повідомленням, відповіді з кешу, сторонній кеш чужої версії не віддається. Працює на підробному середовищі воркера.
- `updates.spec.ts`, `register.spec.ts`, `install.spec.ts`, `online.spec.ts`: потік оновлення, реєстрація, прибирання воркера в dev, пропозиція встановлення.
- `manifest.spec.ts`: іконки існують і мають заявлені розміри, ярлики й `share_target` ведуть на реальні маршрути, в `index.html` підключені маніфест та іконки.

## Чого автотести не покривають: перевірте на телефоні

Service Worker не запускається у Vitest, а в панелі вбудованого браузера, якою я користувався при розробці, реєстрація воркерів не працює (помилка мережевого рівня панелі, не нашого коду). Тому наскрізну перевірку потрібно зробити руками на справжніх пристроях після деплою.

**Android, Chrome**

- [ ] Відкрити сайт: через кілька секунд на екрані «Профіль» з’являється картка «Встановіть Bookshelf», а в меню Chrome пункт «Встановити застосунок»
- [ ] Встановити: значок на головному екрані круглий, без білих країв (maskable), назва «Bookshelf»
- [ ] Запуск зі значка: без адресного рядка, строка стану в кольорі застосунку
- [ ] Довге натискання на значок: ярлики «Додати цитату» і «Статистика»
- [ ] Увімкнути режим польоту й відкрити застосунок: показується оболонка, потім екран «Немає з’єднання»; після вимкнення режиму кнопка «Повторити» повертає на ту саму сторінку
- [ ] У Chrome виділити текст на будь-якій сторінці → «Поділитися» → Bookshelf: відкривається «Нова цитата» з цим текстом
- [ ] Картка цитати → «Поділитися» відкриває системне вікно з картинкою

**iPhone, Safari**

- [ ] «Поділитися» → «На початковий екран»; на екрані «Профіль» до цього видно підказку, як це зробити
- [ ] Значок і назва правильні; запуск без рядка Safari
- [ ] Вхід зберігається між запусками (кука сесії тримається 30 днів)
- [ ] Картка цитати: «Поділитися» відкриває системне вікно. Якщо iOS відмовляє («Не вдалося підготувати картинку»), повідомте: це відомий ризик втрати жесту користувача між натисканням і шерінгом, лікується попереднім малюванням `Blob`
- [ ] Safe area: нижня панель вкладок не заходить під смугу «домой» жестів

**Оновлення версії (будь-який телефон)**

- [ ] Встановити, потім задеплоїти будь-яку зміну; відкрити застосунок: з’являється банер «Доступна нова версія», «Оновити» один раз перезавантажує і застосовує зміни

**Якщо щось не так:** на сторінці `chrome://serviceworker-internals` (Android через `chrome://inspect`) видно стан воркера; помилка встановлення воркера зазвичай означає, що якийсь файл зі списку не віддався (404 після деплою).
